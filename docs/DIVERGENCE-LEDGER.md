# Divergence Ledger

Where a shared module differs between the engine and a consumer's former copy
(`rusty-conduit`, `rusty-conduit-ssh`, `rusty-conduit-switch`), or where the engine changes
behavior a consumer relied on, the difference is recorded here with a decision. No difference is
dropped silently. Each consumer's entries are listed in that CLI's release notes.

## Decisions

| Decision | Meaning |
| :--- | :--- |
| **keep** | The behavior becomes engine behavior for every consumer. |
| **option** | The behavior becomes an engine setting; a consumer sets it to keep its old behavior. |
| **fix** | A bug in one copy. The engine carries the corrected behavior, and the change is listed in that CLI's changelog. |

## Entry format

Each entry records: an ID, the module, the consumers affected, what differs, the decision, and where
it landed (milestone and test).

## E1 — Extraction baseline (`rusty-conduit-switch`)

The engine was extracted from `rusty-conduit-switch` `main` at `69b0c41` (`chore: add CI/Release
workflows and set version to 0.0.1-beta.1`). On `feat/one-engine` (`1e317d4`), `-switch` depends on
the engine and re-exports the old module paths.

| ID | Module | Consumers | Difference | Decision | Landed |
| :--- | :--- | :--- | :--- | :--- | :--- |
| E1-01 | `filter`, `http`, `logging`, `mitm`, `mux`, `net`, `router`, `server`, `socks`, `upstream` | `-switch` | None. Moved unchanged, with their unit tests. | keep | E1. `-switch` suite passes, and `test-route` output is byte-identical to `main` on its fixtures. |
| E1-02 | `routing` (config and snapshot types) | `-switch` | Config-file loading stays in the CLI. The engine takes a `RoutingInput` and returns a typed `RoutingError`; `-switch` maps it with `From<RoutingError>`. Error text is unchanged. | keep | E1 |
| E1-03 | `mitm`, `server` | `-switch` | The CLI's MITM and listener settings are passed as engine structs (`MitmOptions`, `ServerOptions`) instead of the CLI `Config`. Behavior is unchanged. | keep | E1 |

The `rusty-conduit` and `rusty-conduit-ssh` copies are compared module by module in E3 and E4.
Known areas to reconcile then: about 50 differing lines in `logging.rs`, and the `socks/*`
differences in `-ssh`. Each will get its own entry below.

| ID | Module | Consumers | Difference | Decision | Landed |
| :--- | :--- | :--- | :--- | :--- | :--- |

| E3-03 | `http`, `socks` | `rusty-conduit` | Bad `CONNECT` target `400` body changed from `invalid CONNECT target` to `CONNECT target must be host:port`; diagnostic `ERROR`/`INFO`/`DEBUG` wording now uses the engine's unified format. ## M — Maintenance after the CLI ports

Engine changes made after E5 that change behaviour every consumer inherits.

| ID | Module | Consumers | Difference | Decision | Landed |
| :--- | :--- | :--- | :--- | :--- | :--- |
| M-01 | `server` | all | Listeners are now bound through `bind_listener`, which requests a listen backlog of `LISTEN_BACKLOG` (4096) instead of the 128 that `TcpListener::bind` requests. The kernel still caps it (`net.core.somaxconn`, 4096 by default on Linux ≥ 5.4; `kern.ipc.somaxconn`, 128 by default on macOS). `SO_REUSEADDR` stays on for non-Windows platforms. Connection bursts larger than 128 no longer overflow the queue on Linux. | keep | `src/server.rs` (`bind_listener`, `backlog_queues_more_than_128_connections`) |
| M-02 | `logging` | all, GUI | Access-log files (`--http-access-log`, `--socks-log`) were flushed only when the 8 KiB write buffer filled or at shutdown, so a quiet proxy's file could stay empty and a hard kill lost up to 8 KiB. The writer task now drains every queued record and then flushes once the queue is empty: bursts still write in large blocks, and idle records reach the file at once. `stdout` output was already flushed per record. | fix | `src/logging.rs` (writer task, `file_sinks_flush_when_the_queue_drains`) |
| M-03 | `mitm`, `http` | all | `MitmOptions` gains `upstream_tls: UpstreamTlsVerification`, and the MITM upstream TLS connection can now skip certificate verification. `Strict` (the default) keeps the former behaviour: the OS trust store verifies every upstream certificate. `AllowInsecureHosts(Vec<FilterRule>)` accepts invalid or self-signed certificates only for targets that match an exact domain, `*.domain`, IP, or CIDR rule and verifies every other target strictly; an empty list is strict. `InsecureAll` accepts any upstream certificate ("blind trust", unsafe). Both insecure modes still verify TLS 1.2/1.3 handshake signatures. `MitmState::from_options` and `from_pem_bytes` follow the option; `build`, `from_pem_bytes_with_upstream`, `platform_client_config`, and `client_config_with_roots` are unchanged. Adding the field breaks code that builds `MitmOptions` with a struct literal and no `..Default::default()` (released as 0.5.0). | option | `src/mitm/mod.rs` (`UpstreamTlsVerification`), `src/http/mitm_tunnel.rs` (`upstream_client_config`, `SelectiveServerCertVerifier`, handshake tests) |
| M-04 | `http`, `server` | all, GUI | Errors the proxy generates itself (`400`, `403`, `502`, `504` on the forward, `CONNECT`, and decrypted MITM paths) were short `text/plain` bodies. They are now HTML pages (`Content-Type: text/html; charset=utf-8`, `Cache-Control: no-store`) rendered from an `ErrorPageTemplate`: by default a small unbranded built-in page with no external resources or scripts. Embedders can supply their own template (`from_template`, `from_file`) with `{{status}}`, `{{reason}}`, `{{message}}`, and `{{target}}` placeholders, each HTML-escaped, through `EngineHandlers::with_error_page`, `HttpProxy::with_error_page`, or `MitmInterceptor::with_error_page` (overrides the engine's template for decrypted requests). The target is `host` or `host:port` with any userinfo removed. `error_response` keeps its signature and renders the built-in page. Status codes are unchanged, and upstream responses, error statuses included, still pass through unchanged. | option | `src/http/error_page.rs` (`ErrorPageTemplate`), `src/http/mod.rs`, `src/http/forward.rs`, `src/http/tunnel.rs`, `src/http/mitm_tunnel.rs`, `src/server.rs` (`EngineHandlers::with_error_page`), `tests/error_pages.rs` |
| M-05 | `http` (MITM) | all, GUI | A decrypted HTTP/2 tunnel used one upstream HTTP/2 connection for its whole life. Once the origin closed it (GOAWAY after an idle timeout or a request limit, or a reset), the client's HTTP/2 connection to the proxy stayed open and every later request on it was answered `502 upstream request failed`, so browsers failed after a while. The tunnel now redials the origin through the same decision on the next request, as the HTTP/1.1 path already did. A request the origin dropped unanswered is resent once on the new connection when it was never written, or when it is idempotent and has no body; any other request still gets `502`. If a redial no longer negotiates `h2`, requests in hand go out over one-off HTTP/1.1 connections and the client is sent GOAWAY so it reconnects. `te: trailers`, the one `TE` value HTTP/2 allows (gRPC needs it), is now forwarded on HTTP/2 instead of stripped. | fix | `src/http/mitm_tunnel.rs` (`H2Tunnel`, `h2_pick`, `forward_h2`, `upstream_dropped`), `tests/mitm_h2_upstream_reconnect.rs` |
| M-06 | `http` (MITM) | all, GUI | Decrypted HTTP/2 used hyper's default 16 KiB header-block limit (`SETTINGS_MAX_HEADER_LIST_SIZE`) toward both the client and the origin. Sites whose response headers exceed it (for example `gemini.google.com`, about 26 KiB from a long `content-security-policy`) failed with `502` and `http2 error: stream error detected: unspecific protocol error detected`, though browsers load them directly and HTTP/1.1 through the proxy worked; large request cookies hit the same limit. Both sides now accept 256 KiB (`H2_MAX_HEADER_LIST_SIZE`, what Chrome advertises). Upstream request failures are now logged with their full error chain instead of only hyper's error kind. | fix | `src/http/mitm_tunnel.rs` (`H2_MAX_HEADER_LIST_SIZE`, `error_chain`), `tests/mitm_h2_upstream_reconnect.rs` (`h2_relays_headers_larger_than_16k`) |
| M-07 | `mitm`, `routing`, `router`, `http` | all, GUI | Added MITM bypass support in two forms: `MitmOptions::bypass_hosts: Vec<FilterRule>` (stored on `MitmInterceptor`, checked via `should_bypass`) and per-rule `RuleConfig::bypass_mitm: bool` (`#[serde(default)]`, propagated onto `RouteDecision::bypass_mitm`). When MITM is enabled on `HttpProxy` and a `CONNECT` either matches `bypass_hosts` or a rule with `bypass_mitm = true`, dispatch hands the connection to the opaque `CONNECT` tunnel (`mitm=false`) instead of intercepting TLS. Default behaviour (empty `bypass_hosts`, `bypass_mitm = false`) is unchanged. Adding fields to `MitmOptions`, `RuleConfig`, and `RouteDecision` breaks struct literals without `..` (released as 0.6.0). | option | `src/mitm/mod.rs` (`MitmOptions::bypass_hosts`), `src/routing.rs` (`RuleConfig::bypass_mitm`), `src/router/mod.rs` (`RouteDecision::bypass_mitm`), `src/http/mod.rs` (`mitm_connect`), `src/http/mitm_tunnel.rs` (`MitmInterceptor::with_bypass_hosts`, `should_bypass`), `src/http/tunnel.rs` (`handle_resolved`), `tests/mitm_counters.rs` |
| M-08 | `http` (MITM) | all, GUI | `MitmInterceptor::should_bypass` compared a `CONNECT` host against `bypass_hosts` domain rules as written, so `Example.COM` or `example.com.` slipped past an `example.com` bypass and was intercepted. Non-IP hosts are now normalized with `filter::normalize_domain` (lower-case, trailing dot removed) before matching, as the global filter already did. | fix | `src/http/mitm_tunnel.rs` (`should_bypass`, `should_bypass_normalizes_case_and_trailing_dot`) |
| M-09 | `http`, `server` | all, GUI | Three resource bounds. (1) HTTP/1.1 connections had no header-read deadline, so a client sending headers slowly (slowloris) held a connection slot forever; the server now closes a connection whose request headers do not arrive within `DEFAULT_HEADER_READ_TIMEOUT` (30 s), configurable with `HttpProxy::with_header_read_timeout` (`None` disables it). (2) Decrypted MITM HTTP/2 now advertises `SETTINGS_MAX_CONCURRENT_STREAMS` = 256 (`H2_MAX_CONCURRENT_STREAMS`) to the client instead of hyper's unbounded default, and both MITM HTTP/2 sides use an adaptive flow-control window. (3) When `drain_timeout` expires on shutdown, connection tasks still running are now aborted (`ConnectionTasks::abort_all`) instead of being left to run after `Server::run` returns. | fix / option | `src/http/mod.rs` (`DEFAULT_HEADER_READ_TIMEOUT`, `header_read_timeout_closes_silent_clients`), `src/http/mitm_tunnel.rs` (`H2_MAX_CONCURRENT_STREAMS`), `src/server.rs` (`ConnectionTasks`, `drain_timeout_aborts_stuck_connection_tasks`) |
| M-10 | `server` | all, GUI | Accepted client sockets now get `TCP_NODELAY` (a failure is logged at `DEBUG` and the connection proceeds), so small proxy writes such as `CONNECT` replies and TLS handshake records are no longer delayed by Nagle's algorithm. Upstream `direct` sockets already set it. | keep | `src/server.rs` (`accept_loop`, `accepted_client_sockets_get_tcp_nodelay`) |
| M-11 | `routing`, `router`, `http`, `socks` | all, GUI | Rules with `resolve_dns = true` resolved the hostname with a blocking lookup inside the router, stalling a Tokio worker. When a table consulted for the inbound has such a rule (`Router::needs_dns`) and the host is not an IP literal, the engines now resolve it asynchronously first (`resolve_route_async`: `tokio::net::lookup_host`, bounded by the connect timeout, empty on error, never cached) and route with the answers (`Router::route_with_ips`, `RouteResolver::resolve_with_ips`; custom resolvers default to the old `resolve`). Decisions are unchanged; a lookup that times out matches like a failed lookup. | keep | `src/routing.rs` (`resolve_route_async`, `RouteResolver::resolve_with_ips`), `src/router/mod.rs` (`needs_dns`, `route_with_ips`), `src/router/condition.rs`, `src/http/`, `src/socks/mod.rs` |
| M-12 | `http` (MITM), `router` | all, GUI | Each intercepted connection got its own server TLS session state, so clients could never resume a TLS session with the proxy; intercept configs now share one `ServerSessionMemoryCache` (4096 entries, `SERVER_SESSION_CACHE_SIZE`) and one `ring` ticketer, which allows session-ID and ticket resumption. The upstream `ClientConfig` is pre-built for the common ALPN offers (`UpstreamTlsPool`) instead of cloned on every dial. Separately, any URL rule anywhere in the active tables used to force per-request routing of every decrypted `CONNECT`; now only a `CONNECT` whose `host:port` some URL rule could match (`Router::host_may_match_url_rules`, conservative, no DNS) is routed per request, and all others are routed once per tunnel. Decisions are unchanged. | keep | `src/http/mitm_tunnel.rs` (`MitmInterceptor::new`, `UpstreamTlsPool`, `intercept`), `src/router/mod.rs` (`host_may_match_url_rules`), `src/router/condition.rs` (`may_match_host_port`) |
| M-13 | `net`, `upstream` | all, GUI | A hostname that resolved to several addresses was dialed one address at a time, so an unreachable first address (often IPv6) cost the full connect timeout. Multi-address dials now use RFC 8305 Happy Eyeballs (`connect_happy_eyeballs`): addresses interleaved by family, a new attempt every 250 ms (`HAPPY_EYEBALLS_DELAY`) or as soon as one fails, the first connected socket wins, all bounded by the same deadline. IP literals still make a single attempt. | keep | `src/net.rs` (`connect_happy_eyeballs`, `interleave_addrs`) |
| M-14 | `upstream` | all, GUI | A failover chain retried a dead primary profile on every dial. A profile whose dial (or dial timeout) fails is now skipped for `DEFAULT_FAILOVER_COOLDOWN` (3 s) in multi-entry chains while another entry is not cooling; after the cooldown one dial claims a probe, and success clears the mark. Skipped entries are still tried last, in order, if every live entry fails, so a chain never fails only because of the cooldown. `RouteBlocked` and filter denials never mark a profile. Configure with `ProfileRegistry::with_failover_cooldown` (`Duration::ZERO` restores the former behaviour). `with_timeout` now builds its error context lazily. | option | `src/upstream/mod.rs` (`DEFAULT_FAILOVER_COOLDOWN`, `ProfileRegistry::with_failover_cooldown`, `FailoverDialer::dial`, `failover_cooldown_*` tests) |
| M-15 | `net`, `mitm`, `logging`, `http`, `socks` | all, GUI | Throughput and overhead only; no output changes. Relays use 32 KiB buffers per direction (`RELAY_BUFFER_SIZE`, was 8 KiB), `PrefixedStream`/`UpstreamStream`/`CountingStream` forward vectored writes, and `PrefixedStream` reads through a cursor. `CertCache` evicts its oldest entry in amortized O(1) (FIFO queue). Disabled `DEBUG`/`VERBOSE` diagnostics no longer format their message (`log_debug!`/`log_verbose!`). Access lines are encoded straight into one pre-sized buffer, byte-identical in text and JSON. With HTTP or SOCKS access logging off, no record is built and the clock is not read. `AccessGuard::drop` queues its record with `try_send` and spawns a task only when the 4,096-record queue is full. A SOCKS record's `ts` is now computed when the record is emitted, as the current time minus the session's elapsed time; it can differ from the former value by clock adjustments made during the session. | keep | `src/net.rs` (`RELAY_BUFFER_SIZE`, `PrefixedStream`), `src/mitm/cache.rs`, `src/logging.rs` (`log_debug!`, `TextEncoder`, `JsonRecord`, `AccessLogger::try_log_http`), `src/http/mod.rs` (`AccessGuard`), `src/socks/mod.rs` (`Session::finish`) |
